# F29 — Git Sync repositories

On an automation backend with the remotes API (`GET /api/automation/v1/git-sync/remotes`),
the Git Sync page keeps any number of repositories per organization. The header
has a subtitle, the default-repository help line and an **Add repository**
button that opens a **New repository** form (the configuration form in create
mode, with a Label field and `Add` / `Add and sync now` / `Cancel`). Each
repository is a card headed by its label (or its URL without credentials) with
pills (`Default` on the default one, enabled, encryption), **Sync now** and the
activity row, the status fields plus an **Automations** count, and the buttons
**Configure** (folds the configuration form in and out), **Make default**
(absent on the default) and **Remove** (confirmed). A **Last sync error** banner
sits on the card it belongs to. An **Automations** section lists every live
automation with a picker of the repository it syncs to. Without a remotes API
(404) the page falls back to the single-repository page that F24 maps.

Source: `src/routes/automation-git-sync.tsx`, `src/components/features/automations/git-sync/git-sync-remote-card.tsx`, `src/components/features/automations/git-sync/git-sync-assignments-section.tsx`, `src/components/features/automations/git-sync/git-sync-config-form.tsx`, `src/components/features/automations/git-sync/git-sync-overview-section.tsx`, `src/hooks/query/use-git-sync.ts`, `src/hooks/use-git-sync-activity.ts`, `src/types/git-sync.ts`, `src/utils/git-sync-repo-url.ts`.

## Sub-features

- `F29.open`: with the remotes API the page shows the h1 `Git Sync`, the subtitle `Keep each project's automations in its own git repository. ...`, the help line `New automations, and automations not assigned to a repository, sync to the default repository.` and **Add repository** in the title row; there is no `Sync Status` card and no always-open form.
- `F29.empty`: with no repository the page shows `No repositories yet. Add one to start syncing automations.` and nothing else below the header (no cards, no Automations section).
- `F29.add-form`: **Add repository** hides itself and opens the **New repository** form: Label (optional), Enable Git Sync, interval, Repository URL (required), branch, path, author, token and encryption key, with no clear-token or clear-key switches; `Add` and `Add and sync now` stay disabled until a field changes; **Cancel** closes it without a request.
- `F29.add`: `Add` checks the repository is reachable, creates it (toast `Repository added.`) and the first repository becomes the default: its card has `data-default="true"`, the `Default` pill, no **Make default** button, counts the unassigned automations, and opens with its configuration form showing (Label filled in).
- `F29.sync-now`: each card's **Sync now** runs that repository's cycle: its own activity row goes `Syncing...` → `Sync complete`, Pending changes drops to `0`, the card shows the short commit, and the bare repository gets `<path>/<slug>/automation.yaml` on the configured branch.
- `F29.add-and-sync`: `Add and sync now` adds a second repository (no label: the heading is the URL without credentials), which is not the default (`data-default="false"`, **Make default** present, Automations `0`), and runs its cycle right away.
- `F29.assignments`: the **Automations** section lists one row per live automation (name and, once synced, slug) with a select whose options are the repositories' names, the default suffixed ` (Default)`; an automation nobody assigned shows the default.
- `F29.move`: picking another repository calls `PUT /api/automation/v1/git-sync/assignments/<automation-id>` (toast `Automation moved.`); the counts move with it, the new repository exports it on its next cycle and the old repository's next cycle commits the removal of its folder.
- `F29.configure`: **Configure** toggles the card's configuration form (`aria-expanded`, label `Hide configuration`), which edits that repository only; saving a new Label (toast `Git Sync settings saved.`) renames the card heading and the select option.
- `F29.conflict`: adding a repository with the same URL, branch and path as an existing one is refused (409) with the backend's toast `Another repository configuration already syncs this repository, branch and path. ...` and the form keeps its values.
- `F29.make-default`: **Make default** (toast `Git Sync settings saved.`) moves the `Default` pill and the ` (Default)` suffix to that repository, the button to the previous default, and the legacy `GET /api/automation/v1/git-sync/status` now reports the new default.
- `F29.sync-failure`: a failing cycle shows `Sync failed` and the **Last sync error** banner on that card only; the other cards stay clean.
- `F29.remove`: **Remove** opens a confirmation (`Remove this repository from Git Sync? ...`); Cancel sends nothing, Remove deletes it (toast `Repository removed.`), the card disappears and the bare repository on disk keeps its commits.
- `F29.no-default`: removing the default leaves no default: the remaining cards all show **Make default**, their counts exclude the orphaned automations, the Automations section says `Not assigned to a repository: N` and the select shows a disabled `Not configured` option; promoting a card ends that state.
- `F29.phone`: at 390 px the title row wraps (**Add repository** under the help text), cards fit the viewport without horizontal overflow and keep two columns of fields.
- `F29.fallback`: on an automation backend whose remotes API answers 404 (every PyPI release up to 1.23.1, including the pinned one) the page is the single-repository page: no **Add repository**, a `Sync Status` card and the always-open form, and F24's recipes apply.

## How to get to it (user POV)

- Sidebar **Automate** (`sidebar-automations-link`), then the **Git Sync** button in the dashboard header (`automations-git-sync`; see F21). Only users who can manage automations see it (always, locally).
- Direct URL `/automations/git-sync`.
- Which page appears depends on the automation backend, not on the user: one `GET /api/automation/v1/git-sync/remotes` decides (200: this family; 404: F24).
- No command-menu entry, keyboard shortcut or Automate sub-navigation tab leads here; leave with **Back to Automations** (a link, not a button).

## Gotchas

- Which page renders is decided by the backend, once per load: `GET /api/automation/v1/git-sync/remotes` 200 is this family, 404 is F24's single-repository page (and a 404 on `git-sync/status` as well is F24's unsupported state). Any other failure with no cached list shows the generic error panel with **Retry** (F24's `F24.error-state` recipe applies). Health and permission gates (`F24.backend-down`, `F24.no-access`, `F24.loading`) are shared with F24 and mapped there.
- No PyPI release of `openhands-automation` ships the remotes API as of 1.23.1; the default `control-openhands launch` (pinned 1.22.0 at the time of writing) therefore drives F24, not this family. Pass `--automation-path` or `--automation-ref` explicitly and record which; shell `OH_AUTOMATION_*` variables are not forwarded.
- Test ids repeat once per card (`git-sync-now-button`, `git-sync-enabled-pill`, `git-sync-activity-row`, `git-sync-error-banner`, `git-sync-configure-button`, the form inputs). An unscoped selector matches several elements and the click lands on the first card, which is the default one: scope with `[data-remote-id="<id>"]` (or `[data-default="true"]`). The **New repository** form is the one place a form input is unique while it is open, and even then only if no card has its configuration unfolded.
- The first repository added becomes the default whatever its label; `PUT /api/automation/v1/git-sync/remotes/<id>` with `{"is_default": false}` is refused (`422`, "An organization gives up its default remote by making another one the default, not by unsetting it."), and the UI offers no control for it: the only way to change the default is **Make default** on another card. Removing the default leaves the organization without one until a card is promoted.
- Automation counts are live but asymmetric: the default counts its assigned automations plus every unassigned one (which it adopts on its next cycle, see `F29.sync-now`); the others count only automations assigned to them. A moved automation leaves the old repository's tree only on that repository's next cycle, and the removal commit is a plain `Sync automations from agent server`.
- A card just added opens with its configuration showing; after a reload every form is folded. **Configure** is per card, and the create form and a card form can be open at once.
- The create form has no clear-token or clear-key switches (nothing is stored yet); the same form on a card has them. Both run the reachability check (`POST .../remotes/check` for a new repository, `POST .../remotes/<id>/check` for an existing one) only when URL, branch or token changed, with the same second-Save override as F24.
- A conflicting repository is detected after the reachability check and reported with the backend's own `detail` as the toast, so a conflict between two reachable configurations costs one `git ls-remote` first. The same 409 applies when a card's Configure form is saved onto another card's URL, branch and path.
- The list is polled every 15 s, and every 3 s while any card's cycle is being followed, so a cycle another card or the backend's interval started shows up on its own row; the activity row itself is page state and disappears on reload (the banner and the commit hash do not).
- Cards are ordered default first. After **Make default** the promoted card moves to the top, which also reorders the select options; do not rely on `nth=` after a promotion.
- `browser text` on the confirmation modal includes the two button labels after the message; the modal's buttons are `cancel-button` and `confirm-button`, not Git-Sync-specific ids.
