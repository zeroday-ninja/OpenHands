# F33 — Workbench

`/workbench` and `/workbench/:projectId` provide a visual-first, multi-repo workspace shell for Agent Canvas backed by one JSON file per workspace at `.openhands/workbench.json`. The projects home lists projects spanning one or more repositories, creates new projects, and initializes an empty workspace either from a built-in example or from a blank document. Opening a project presents a Design view (repo groups, typed parts with ports and wires, selection focus and details, context menus, tooltips, inline rename, drag-and-wire, overlays, repo-level zoom, freehand highlights, and undo/redo) and a Work view (sprint tabs, backlog, epic filters, five draggable kanban lanes, burndown, sprint planning/start/end with carry-over, story splitting, and autopilot) flanked by two collapsible drawers that fold into icon rails — a left team/library/repos panel and a right Architect/PM chat panel that focuses on the current selection and binds a real workspace conversation. Edits autosave to `.openhands/workbench.json` via `FileClient`, the toolbar offers a one-click escape back to the classic UI, and on a Cloud backend or with no backend the route reports itself as unsupported.

Source: `src/routes/workbench.tsx`, `src/routes/workbench-project.tsx`, `src/components/features/workbench/`, `src/api/workbench-service/`, `src/hooks/query/use-workbench.ts`, `src/hooks/mutation/use-save-workbench.ts`, `src/hooks/use-refresh-workbench-on-agent-edit.ts`, `src/stores/workbench-store.ts`, `src/stores/workbench-layout-store.ts`, `src/utils/workbench/`, `src/types/workbench.ts`.

## Sub-features

- `F33.open`: the sidebar **Workbench** link (`sidebar-workbench-link`, between **Project map** and **Automate**) and the direct URL `/workbench` open the Workbench and mark the row `aria-current="page"`; the sidebar link is hidden on a canvas locked to a Cloud host, and Workbench is not listed in the command menu.
- `F33.pin-as-home`: hovering the sidebar **Workbench** row reveals `sidebar-pin-home-toggle-workbench`; pinning makes `/` redirect to `/workbench`, and unpinning restores `/` to the default home (`/map` on a local backend).
- `F33.empty-states`: with no `.openhands/workbench.json`, `/workbench` renders `workbench-empty-missing` with **Start from the example** (`workbench-start-example`) and **Start blank** (`workbench-start-blank`), both writing `.openhands/workbench.json` via `FileClient` and surviving a reload; a blank document shows `No projects yet. Create one below.` with **Create project** disabled (no repos exist); a corrupt file renders `workbench-empty-error` with the parser failure; and an unknown project id (`/workbench/<id>`) renders `workbench-empty-no-project` with an **All projects** link back to `/workbench`.
- `F33.projects-home`: `/workbench` lists project cards (`workbench-project-<id>`) with repo pills and part/open-story counts, plus the **New project** form (`workbench-new-project-name`, `workbench-pick-repo-<id>` toggles, `workbench-create-project`, disabled until a name and at least one repo are chosen); creating a project opens `/workbench/:projectId`, autosaves to `.openhands/workbench.json`, and survives a reload; inside a project, `workbench-project-select` switches projects and **All projects** (`workbench-all-projects`) returns to `/workbench`.
- `F33.design-canvas`: `/workbench/:projectId` opens in Design view (`workbench-canvas`) drawing only that project's repo groups (`g[data-testid^="workbench-group-"]`), parts (`workbench-part-*`) with kind badges and status labels, and wires (`workbench-wire-*`).
- `F33.selection-and-tooltip`: clicking a part selects it (`aria-pressed="true"`), dims non-neighbours (`opacity-30`), populates `workbench-focus-chips` and collapsible `workbench-details` (kind, status, repo, files, tests, drift/gate/unsure, clickable wire links); Shift/Ctrl-clicking toggles multi-selection; clicking a group grip (`workbench-group-grip-<id>`) selects all parts in that repo; Escape or clicking empty paper clears selection; hovering parts, grips, ports, or controls shows the shared `workbench-tooltip` (`role="tooltip"`) after 350 ms.
- `F33.context-menus`: right-clicking opens `workbench-context-menu` tailored to the target — part (Ask the Architect, New story for this part, Rename `F2`, Status submenu, Move to repo submenu, Delete `Del`), wire (Wire label submenu, Ask the Architect, Delete), repo group (Select its N parts, Ask the Architect, Crawl / Crawl again, Add a part submenu, Rename, Remove from this project), and empty paper (Add a part here when inside a group, Fit to view `0`, Show repos only / Show parts, Highlight `H`, Clear highlights, Undo, Redo) — and closes on Escape or outside click.
- `F33.rename-delete-undo`: double-clicking a part (or `F2` / menu **Rename**) opens inline `workbench-rename-<id>` (Enter commits, Escape cancels); pressing `Delete` / `Backspace` (or menu **Delete**) removes the selection and shows `workbench-toast` with **Undo** (`workbench-toast-undo`); toast **Undo**, toolbar **Undo** (`workbench-undo`) / `Ctrl+Z`, and **Redo** (`workbench-redo`) / `Ctrl+Y` step through the edit history.
- `F33.drag-and-wire`: dragging a group title bar (`workbench-group-grip-<id>`) moves the repo group; dragging a part repositions it on the 10-unit grid (and drops into another repo group move it there); dragging from a part's port (`workbench-port-<id>`) to another part draws a new `planned` wire (`workbench-wire-<from>-><to>`) with a toast and Undo.
- `F33.side-panel-and-drops`: the left panel (`workbench-left-panel`) lists the 7 team roles (`workbench-role-*`), scheduled/idle agents (`workbench-agent-*`), the 9-kind **Add a part** library (`workbench-library-*`), and **Other repos** (`workbench-repo-chip-*`); clicking or dragging an other-repo chip adds that repo group to the project; dragging a team role onto a part sends them there (`Sent to <part>` toast); dragging a library tile onto a repo group is intended to create a planned part and open inline rename.
- `F33.overlays-and-levels`: toolbar buttons toggle the four overlays — **Agents** (`workbench-overlay-agents`, on by default, showing `workbench-agent-badge-*` and trails), **Changes** (`workbench-overlay-changes`, showing lines changed and a bar), **Tests** (`workbench-overlay-tests`, showing `% tested`), and **Drift** (`workbench-overlay-drift`, showing `!` badges); **Show repos only** (`workbench-level`, `aria-pressed`) switches to `workbench-repo-box-<id>` cards with inter-repo wire counts and clicking a repo box returns to parts view framed on it; **Zoom in** (`workbench-zoom-in`), **Zoom out** (`workbench-zoom-out`), and **Fit to view** (`workbench-fit` / `0`) control the camera.
- `F33.highlight-tool`: pressing `H` or clicking `workbench-tool-highlight` activates the freehand highlight tool (`V` or `workbench-tool-select` returns to Select); dragging draws a numbered `workbench-highlight-<id>` outline, toasts `Highlighted <n> parts`, and reveals **Clear highlights** (`workbench-clear-highlights`), which clears all highlights.
- `F33.drawers-and-rails`: both side drawers collapse into 48 px icon rails (`workbench-left-rail`, `workbench-right-rail`) via their chevrons (`workbench-left-close`/`open`, `workbench-right-close`/`open`) or `[` and `]`, keeping team/library/repo icons on the left rail and Architect/PM persona buttons (`workbench-rail-talk-arch`, `workbench-rail-talk-pm`) on the right rail; drawer state persists in `localStorage` (`openhands-workbench-layout`) across reloads.
- `F33.autosave`: edits mark the buffer dirty (`workbench-save` enables and reads `Save now`), then autosave after ~1.2 s (`Saving…` → `Saved`, disabled) to `.openhands/workbench.json` via `FileClient`, or save immediately when **Save now** is clicked; changes survive `browser reload`.
- `F33.work-board`: clicking **Work** (`workbench-mode-work`) switches the stage to the kanban board (`workbench-board`) on the active sprint (`workbench-sprint-tab-s12`) with five lanes (`workbench-lane-backlog`, `build`, `test`, `review`, `done`), sprint header (`workbench-sprint-header`, `workbench-sprint-totals`, velocity, burndown SVG), epic filters (`workbench-epic-*`), a **Backlog** tab (`workbench-backlog-tab`) grouped by epic, and card part links that jump back to Design view with that part selected.
- `F33.work-stories`: submitting `workbench-new-story` adds a story to the shown sprint (or Backlog) in `To do`; dragging a story card (`workbench-card-*`) between lanes or onto another sprint/Backlog tab moves it with a toast + Undo; right-clicking a card opens its context menu (Start this story, Ask PM, Rename `F2`, Move to stage/sprint, Epic, Points, Split into smaller stories, Show on the design map, Delete `Del`), and splitting replaces a >=2-point story with two half-sized stories.
- `F33.work-sprints`: on a planned sprint (`workbench-sprint-tab-s13`), **Plan sprint** (`workbench-plan-sprint`) pulls backlog stories up to team velocity and **Start sprint** (`workbench-start-sprint`) activates it; on an active sprint, **End sprint** (`workbench-end-sprint`) closes it with a review summary, updates velocity, carries unfinished stories forward, and activates the next planned sprint; **New sprint** (`workbench-new-sprint`) adds a planned sprint, clicking the sprint goal opens `workbench-sprint-goal-input`, and **Autopilot** (`workbench-autopilot`) toggles autonomous pickup.
- `F33.chat-context`: the right chat panel (`workbench-chat`) reflects the current selection in `workbench-focus-chips` (with per-chip remove and `workbench-focus-clear`), toggles between **Architect** (`workbench-persona-arch`) and **Project manager** (`workbench-persona-pm`) in `workbench-focus-heading` and the input placeholder, and expands **Show what the agent will be told** (`workbench-context-preview`) with the exact persona brief, project name, absolute `.openhands/workbench.json` path, and selected items.
- `F33.chat-send`: sending (`workbench-chat-send`) without an LLM profile displays error toasts (`The conversation could not be started.` and `LLM profile 'default' not found`) and leaves `data-conversation-id` unset; with an LLM profile configured, sending starts and binds a real workspace conversation (`data-conversation-id`) carrying the exact context message as its first `MessageEvent`, revealing **Open full screen** (`workbench-open-conversation`) and **New Conversation** (`workbench-detach-conversation`); model-backed replies and `useRefreshWorkbenchOnAgentEdit` live reload after agent edits are blocked without a live model key.
- `F33.classic-view`: clicking **Classic view** (`workbench-classic-link`) in the Workbench toolbar navigates back to `/conversations`.
- `F33.phone`: at phone width (`390×844`), `/workbench` fits cleanly without horizontal overflow; on `/workbench/:projectId`, collapsing both drawers to icon rails leaves the stage usable, whereas default open drawers crowd the stage to zero width and clip the chat drawer off-screen.
- `F33.unsupported`: on a Cloud backend (`workbench-empty-cloud-backend`) or with no backend (`workbench-empty-no-backend`), `/workbench` and `/workbench/:projectId` render an unsupported empty state without reading `.openhands/workbench.json` (positive paths blocked locally; both counts are `0` on a local run).

## How to get to it (user POV)

- Sidebar: **Workbench** (`sidebar-workbench-link`), between **Project map** and **Automate** (hidden on a canvas locked to a Cloud host). Hovering the row reveals its home pin (`sidebar-pin-home-toggle-workbench`).
- Direct URLs: `/workbench` (projects home or empty state) and `/workbench/:projectId` (a specific project, e.g. `/workbench/team`).
- Home redirect: when pinned as home from the sidebar, `/` redirects to `/workbench`; unpinning restores `/` to the default home (`/map` locally).
- Inside a project: **All projects** (`workbench-all-projects`) returns to `/workbench`, the project dropdown (`workbench-project-select`) switches projects, **Design** / **Work** (`workbench-mode-design`, `workbench-mode-work`) switch the stage, `[` / `]` or the drawer chevrons fold/expand the left and right drawers, and **Classic view** (`workbench-classic-link`) returns to `/conversations`.
- Not in the command menu (`Control+k` / `Meta+k` has no Workbench entry).

## Gotchas

- **Prefix collisions on `data-testid`:** both the repo group `<g>` (`workbench-group-<id>`) and its drag handle `<rect>` (`workbench-group-grip-<id>`) start with `workbench-group-`, so count groups with `'g[data-testid^="workbench-group-"]'`. Likewise, both left-panel scheduled agents (`workbench-agent-<id>`) and canvas agent badges (`workbench-agent-badge-<id>`) start with `workbench-agent-`, so scope left-panel agent counts to `'testid=workbench-left-panel >> [data-testid^="workbench-agent-"]'`.
- **SVG elements and `browser text`:** `browser text` uses `innerText` and fails on SVG elements (`Node is not an HTMLElement`). Read wire labels and part labels inside `workbench-canvas` with `browser eval` on `textContent` or `aria-label` / `data-tip`.
- **Horizontal wires and Playwright click visibility:** wires connecting two parts at the exact same Y coordinate (such as `workbench-wire-table->picker`) have an SVG bounding box height of `0`, so Playwright treats them as "not visible" without `--force`. Target a diagonal wire such as `workbench-wire-svc->email` for normal right-click checks, or pass `--force`.
- **Autosave timing (1.2 s) and undo/selection/tab reset:** `WorkbenchPage` autosaves 1200 ms after any edit (`AUTOSAVE_MS`), and `useSaveWorkbench` invalidates `useWorkbench` on success, triggering `hydrate()` with the new revision hash. Until that bug is fixed, chain immediate Undo/Redo assertions in the same shell command before 1.2 s elapses, and wait for `testid=workbench-save >> text="Saved"` before starting a selection-sensitive step so a trailing autosave does not clear selection mid-step.
- **Blank document has no repos:** clicking **Start blank** writes an empty `repos: []` array, leaving the **New project** form with no repo buttons and a disabled **Create project** button until repos are added to `.openhands/workbench.json`.
- **Drawer layout persistence:** `openhands-workbench-layout` in `localStorage` remembers `leftOpen` and `rightOpen` across reloads and visits; a fresh pass on the same browser profile should remove that key or expand both drawers (`[`, `]`) before measuring Design or Work layouts.
- **Canvas centre under open drawers:** in the default fitted framing of `Team workspace` with both drawers open at 1440×1000, the centre of `workbench-canvas` lands over `workbench-part-users`, not empty `data-paper`. Because `onEmptyPointerDown` rejects non-`data-paper` targets, driving the Highlight tool via `browser drag 'testid=workbench-canvas'` requires fitting with drawers open (`browser press 0`) and then folding both drawers (`[`, `]`) so the centre lands on empty `data-paper` (and see the `F33.highlight-tool` known-bug note).
- **Repo drag commits two undo steps and can overlap existing parts:** dropping a repo chip onto the canvas calls `addRepoToProject` and `moveRepo` as two separate `commit()` calls, so a single Undo only undoes the move and leaves the repo in the project. Dropping onto the canvas centre also places the new group behind existing `api-server` parts in SVG z-order; switching to Repo-level view (`workbench-level`) exposes `workbench-repo-box-<id>` unobstructed for right-clicking **Remove from this project**.
- **Shared workspace file location:** `WorkbenchService` resolves `.openhands/workbench.json` via `resolveProjectMapPath`, so without a bound conversation it reads and writes `$OH_VERIFY_RUN/private/home/workspace/project/.openhands/workbench.json` on the local Agent Server host.
- **Workbench is not in the command menu:** `Control+k` / `Meta+k` lists `Project map` (F32) but has no Workbench item.
- **Locked-to-Cloud guard:** `sidebar-workbench-link` and `isPinnableRoute("/workbench")` share the same `getLockedCloudHost() === null` guard as Project map, so neither the link nor pinning is offered on a locked-Cloud canvas.
