# F30 — SOUL.md standing preferences

`/settings/soul` edits the user's `SOUL.md`: a standing brief that the Agent
Server adds to the prompt of every conversation, including ACP runtimes such as
Claude Code and Codex. The page explains what the document is, says whether the
text on screen is the user's own file or the agent server's built-in default,
shows the resolved path and a character count, and offers **Save** and **Revert
to default** (a confirmation, then the file is deleted). Saving empty text does
the same as reverting. Over 65536 characters the page refuses to send anything.
On a Cloud backend, with no backend, or on an agent server without the route it
renders an unsupported panel instead of an error: `GET /api/soul` is optional
and `compatibility.minimumAgentServer` was deliberately not raised for it.

Source: `src/routes/soul-settings.tsx`, `src/components/features/settings/soul/`, `src/api/soul-service/`, `src/hooks/query/use-soul.ts`, `src/hooks/mutation/use-save-soul.ts`.

## Sub-features

- `F30.open`: the settings nav lists **SOUL.md** last (`sidebar-settings-/settings/soul`) and opens a page whose header reads `SOUL.md` / `Your standing preferences, applied to every conversation`, followed by the two description paragraphs (what the document is, and that it reaches ACP agents too).
- `F30.default-state`: with no file of their own the user sees the agent server's default text, the origin pill `Built-in default` (`data-exists="false"`), the resolved path, the character count, and both buttons disabled.
- `F30.dirty-tracking`: **Save** enables only while the text differs from what the server returned, and typing the original text back disables it again; leaving the page discards an unsaved draft without a warning.
- `F30.save`: **Save** writes the text (`PUT /api/soul`), toasts `Your preferences were saved.`, and the page switches to `Your own file` (`data-exists="true"`) with the saved text surviving a reload.
- `F30.character-count`: the count reads `<chars> of 65536 characters` and follows every keystroke.
- `F30.over-limit`: above 65536 characters the page shows `Too long by N characters. The agent server accepts at most 65536.`, marks the textarea `aria-invalid`, disables **Save** and sends nothing.
- `F30.empty-save`: clearing the textarea and saving deletes the file and brings back the built-in default, with the **Save** toast rather than the revert one; whitespace-only text counts as a change, so **Save** offers itself there too.
- `F30.revert`: **Revert to default** asks first (`Delete your SOUL.md and go back to the built-in default? ...`); Cancel sends nothing, confirming toasts `Your SOUL.md was deleted. The agent is back on its built-in default.` and the page is back on the default. The button is disabled while the user has no file of their own and enabled whenever they do, dirty or not.
- `F30.command-menu`: the command menu's `SOUL.md preferences` / `Edit the standing preferences applied to every conversation.` item (`command-menu-option-soul-settings`) opens the page.
- `F30.unsupported`: on an agent server without `GET /api/soul` the page shows `Not available on this backend` / `This agent server does not support SOUL.md yet. Update the agent server and try again.` (`soul-unsupported`, `data-reason="missing-api"`) and no editor, while the nav entry stays. A Cloud backend (`data-reason="cloud-backend"`) and no backend at all (`no-backend`) use the same panel with their own sentence and send no request.
- `F30.phone`: at 390 px the heading, the description, the editor and both buttons stay inside the viewport with no horizontal overflow.

## How to get to it (user POV)

- Settings nav: the gear (`backend-selector-settings-link`) or any settings page, then **SOUL.md** (`sidebar-settings-/settings/soul`), which is the last entry on desktop and in the tablet selector; the phone hub lists it in the same place (F09 owns the nav itself).
- Command menu (`Control+k` / `Meta+k`, or `command-menu-trigger`): **SOUL.md preferences** in the Settings group.
- Direct URL `/settings/soul`.
- Not reachable from a conversation, the composer or the home page; `/settings/soul` is also unreachable on a canvas locked to a Cloud host, where the settings shell redirects to `/settings/app` (F09).
- An improvement program's **Add to SOUL.md** writes into this same document (F31 owns that action); its bullets appear here under a `## Learned preferences` heading.

## Driving it with control-openhands

Preconditions:

- A run whose Agent Server serves `GET /api/soul`. No PyPI release has the route yet (1.56.0, the pin in `config/defaults.json`, answers 404), so launch from a checkout of `OpenHands/software-agent-sdk` that contains it: `export OH_VERIFY_RUN=$(control-openhands launch --new --no-browser --sdk-path <sdk-checkout> --print-run)`, then `control-openhands browser start`, `control-openhands doctor` (`ok`) and `control-openhands onboard --skip`. Record the agent-server version. `control-openhands api GET /api/soul` answers `200` with `"exists": false` and the server's default `content`. No LLM profile is needed: nothing on this page talks to a model.
- The user has no `SOUL.md` of their own at the start: `control-openhands api PUT /api/soul --write --data '{"content":""}'` reports `"exists": false` (arrange, not proof).
- `F30.unsupported` needs a second run on the pinned agent server; it is the last bullet and launches that run itself.

- **Open from the nav (`F30.open`).** Run `control-openhands browser goto /settings/app`, then `control-openhands browser click 'testid=sidebar-settings-/settings/soul' --expect-url '/settings/soul(\?|$)'`. `control-openhands browser text 'testid=settings-screen >> h2'` is `SOUL.md` and `control-openhands browser text 'testid=settings-page-subtitle'` is `Your standing preferences, applied to every conversation`. `control-openhands browser text 'testid=soul-settings-screen'` starts with `SOUL.md is your own standing brief for the agent: how you want it to work, the bar you review at, and the preferences it has learned from you. It is added to the prompt of every conversation.` and continues `It reaches ACP agents such as Claude Code and Codex too, not only the built-in agent.`; `control-openhands browser count 'testid=soul-editor'` is `1`.
- **The built-in default (`F30.default-state`).** `control-openhands browser attr 'testid=soul-origin' data-exists` is `false` and `control-openhands browser text 'testid=soul-origin'` is `Built-in default`. `control-openhands browser text 'testid=soul-path'` is the path `api GET /api/soul --pick path` reports (under the run's private home, for example `$OH_VERIFY_RUN/private/SOUL.md`), and `control-openhands browser value 'testid=soul-content-input'` equals that response's `content`. `control-openhands browser enabled 'testid=soul-save-button'` and `control-openhands browser enabled 'testid=soul-revert-button'` are both `false`.
- **Save an edit (`F30.save`, `F30.dirty-tracking`, `F30.character-count`).** Run `control-openhands browser fill 'testid=soul-content-input' 'QA_SOUL always run the linter before you answer.'`: `control-openhands browser enabled 'testid=soul-save-button'` is `true` and `control-openhands browser text 'testid=soul-character-count'` is `48 of 65536 characters`. Run `control-openhands browser click 'testid=soul-save-button'` and `control-openhands browser wait-text 'Your preferences were saved.' --timeout 5000`. `control-openhands browser text 'testid=soul-origin'` is `Your own file`, `control-openhands browser attr 'testid=soul-origin' data-exists` is `true`, `browser enabled 'testid=soul-save-button'` is `false` again (the draft was adopted) and `browser enabled 'testid=soul-revert-button'` is `true`. - **Too long (`F30.over-limit`).** Run `control-openhands browser network --clear`, then `control-openhands browser fill 'testid=soul-content-input' "$(python3 -c 'print("x"*65537, end="")')"`. `control-openhands browser text 'testid=soul-too-long'` is `Too long by 1 characters. ## Gotchas

- The page never reports a missing route as a failure, so a `404` on `api/soul` in `browser errors` is the unsupported state working, not a bug. Any other failure (a 500, a dropped connection) is the `soul-load-error` panel with **Retry** instead, which needs fault injection and is not mapped (see the index's "Not mapped").
- `compatibility.minimumAgentServer` is not raised for this route: a backend old enough to be refused by the gate never reaches either state, and a backend new enough to pass may still answer 404.
- The textarea is a plain controlled `<textarea>`: `browser fill` works, but writing `.value` with `browser eval` does not reach React and leaves **Save** disabled.
- **Save** is disabled until the text differs from the server's; a value re-typed to the original disables it again. **Revert to default** does not follow the draft at all: it is enabled whenever the user has a file, so it can delete a file whose edits were never saved.
- Saving an empty textarea and reverting both send `PUT /api/soul {"content": ""}`. Only the toast differs, so read the toast to tell which path ran.
- The over-limit guard is in the page, not the backend: the agent server's own `422` for a document above 65536 characters is never reached from here, so it is the Agent Server's contract to verify, not this page's.
- The 65536 limit is counted in UTF-16 units in the page while `size_bytes` from the server is UTF-8, so a document of multi-byte characters reports more bytes than the count shows.
- The server trims the saved text and the response is written straight into the cache, so the textarea can change under the cursor right after Save (a trailing newline disappears). Read the field after the toast, not before.
- An already-open page does not refetch after `api PUT /api/soul --write`: `browser reload` before asserting the UI.
- Toasts last a few seconds: `browser wait-text '<toast>' --timeout 5000` right after the click, or `browser toasts --history` afterwards.
- The confirmation modal's buttons are the shared `cancel-button` and `confirm-button`, and the confirm button reads `Revert to default`, not `Confirm`; `browser text 'testid=confirmation-modal'` includes both labels after the message.
